# 道路ネットワークのグラフ構造

## OSMデータからグラフへの変換

OSMの道路データは**混合マルチグラフ**として表現できる。有向エッジ（一方通行）と無向エッジ（双方向）が混在する。

- **頂点（Vertex）**: OSMノード（交差点、行き止まり）
- **辺（Edge）**: 交差点間の道路セグメント
- **重み（Weight）**: Haversine距離（メートル単位）

## 変換プロセス

### 1. ノード収集
Overpass APIレスポンスから `type: "node"` を抽出し、`id → {lat, lon}` のルックアップテーブルを構築。

### 2. 隣接リスト構築
`type: "way"` の `nodes` 配列から連続するノードペア `(nodes[i], nodes[i+1])` を取り出し、Haversine距離を重みとして双方向のエッジを追加。

```javascript
// 隣接リスト構造
graph.adjacency[nodeId] = [
  { to: neighborId, dist: metersDistance },
  ...
];
```

### 3. 想定規模
近隣エリア（1-2km四方）で約2,000〜10,000ノード、同程度のエッジ数。ブラウザ内で十分処理可能。

## Haversine距離

地球表面上の2点間の大圏距離を計算する公式。

```
R = 6,371,000 m（地球の半径）
a = sin²(ΔΦ/2) + cos(Φ1) · cos(Φ2) · sin²(Δλ/2)
d = R · 2 · atan2(√a, √(1-a))
```

## エージェントの道路上制約

エージェントは任意の緯度経度ではなく、**グラフのエッジ上**に存在する。

```javascript
agent = {
  from: nodeId,        // 出発ノード
  to: nodeId,          // 到着ノード
  progress: 0.0〜1.0,  // エッジ上の位置（線形補間）
  edgeDist: meters,    // エッジの長さ
  speed: m/s,          // 移動速度
  path: [nodeId, ...], // 計算済み経路
}
```

描画位置は `from` と `to` の座標を `progress` で線形補間して求める:
```
lat = from.lat + (to.lat - from.lat) × progress
lon = from.lon + (to.lon - from.lon) × progress
```

## 経路探索（A*アルゴリズム）

### ゾンビ（追跡）
1. 最寄りの人間をユークリッド距離で特定
2. A*でゾンビの現在ノードから人間の現在ノードへの最短経路を計算
3. ヒューリスティック: ユークリッド距離（admissible）

### 人間（逃走）
1. 最寄りのゾンビを特定
2. 現在ノードの隣接ノードのうち、ゾンビから最も遠いものを選択（貪欲法）

### パフォーマンス
- A* on 5,000ノードのグラフ: 約1-5ms
- 100エージェントで0.5秒ごとに再計算: 100-500ms/sec（許容範囲）
- 経路は**毎フレームではなく0.5秒ごと**に再計算

## 感染判定

2つのエージェントの距離が閾値（約8m、度数で約0.00008）未満の場合に接触と判定。

最適化: 同一エッジ上または隣接エッジのエージェントのみをチェックすれば、ペアワイズ比較を大幅に削減できる。

## 関連ツール

- **OSMnx**（Python）: OSMデータをNetworkXグラフとして取得。オフライン解析向け
- **NetworkX**: Pythonのグラフ解析ライブラリ。Dijkstra法等の経路探索
- **ngraph.path / ngraph.graph**: JavaScript用の軽量グラフライブラリ
